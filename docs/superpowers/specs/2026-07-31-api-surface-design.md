# API-Surface Domain — generated from live routes + reconciled (design)

**Status:** approved by owner 2026-07-31 (brainstorm dialogue).
**Program:** sub-project "C" of the *guarded knowledge graph over the codebase*.
Follows D (CLI surface). Catalogs the HTTP API surface from the live app and guards
the committed API contract against drift.

## Goal

The API surface (12 routers, 34 endpoints) is defined in code and *also* exported
as `frontend/openapi.json` (via `make ui-typegen`) — the contract the Next.js
frontend depends on. That contract can go **stale** if a route changes and
`ui-typegen` isn't re-run. Make the surface **catalogued and drift-checked**:

1. A generated `docs/api/index.md` — every endpoint, grouped by router — a complete
   API map for humans and agents.
2. A guard that flags the committed `frontend/openapi.json` being **stale vs the
   live routes** (the "changed the API, forgot the frontend contract" drift), plus
   catalog drift and docs that name a gone endpoint.

## Design decisions (locked in brainstorm)

- **Definition = the live app's routes.** Import `src.main:app` and read its actual
  routes — fully-resolved paths, always matching the code. (Rejected: reading the
  committed `openapi.json` — that is the artifact that drifts, so it can't detect
  its own staleness; rejected: static decorator parsing — fragile router-prefix
  reconstruction.)
- **Endpoint-set granularity.** The freshness check compares the set of
  `(method, path)` pairs, not every schema field. It catches added / removed /
  renamed endpoints — the right altitude for v1. (Field-level request/response
  schema drift is a documented v-next.)
- **`api-check` imports the app**, so it runs in the project env via `make
  api-check` and is **not** wired into the git pre-commit hook (unlike the
  stdlib-only ADR/CLI checks — importing the app is too heavy/env-dependent for a
  commit hook).

## Source of truth — the live app

`reader.load_app()` imports `src.main:app`. From `app.routes` (the `APIRoute`
entries) we derive, per endpoint: HTTP method(s), resolved path, the owning router
module (`route.endpoint.__module__`, e.g. `src.api.routers.exports`), and the route
name/summary. `app.openapi()["paths"]` gives the same surface in OpenAPI shape for
the freshness comparison.

## Generated artifact

- **`docs/api/index.md`** — the catalog: each endpoint as `METHOD /path`, grouped by
  router module, with the route summary. Generated by `make api-index`, never
  hand-edited (guarded for sync). Example:

```markdown
# API surface

## src.api.routers.exports
- `GET /exports/{interview_id}/{lens_name}` — Export an interview×lens OKF bundle

## src.api.routers.files
- `GET /files/` — List ingested files
- `POST /files/` — Ingest a transcript
```

## The guard — `make api-check` (non-blocking)

`python -m tools.api check` returns findings; **never raises, always exits 0**:

1. **`check_openapi_fresh`** (the high-value one) — the set of `(method, path)` in
   the committed `frontend/openapi.json` vs the live app's `app.openapi()`. Any
   endpoint present in one but not the other → `frontend/openapi.json is stale vs
   the code — run make ui-typegen` (with the specific added/removed endpoints
   listed). If `openapi.json` is missing, one finding saying so.
2. **`check_catalog_in_sync`** — `docs/api/index.md` matches the live routes (like
   the `adr-index`/`cli-index` sync checks).
3. **`check_docs_reference_real`** — scan `CLAUDE.md` + `README.md` for backticked
   endpoint mentions (`` `GET /path` `` / `` `POST /path` ``); flag any whose
   `(method, path)` is not a real route. Path templates match structurally (a doc's
   `/exports/{id}/{lens}` matches the route's `/exports/{interview_id}/{lens_name}`
   by segment shape, since param names differ) — see Edge cases.

## Module design — new `tools/api/`

Mirrors `tools/adr` / `tools/cli` reader → render → check → CLI. **Imports the app**
(not stdlib-only), so it is a `make`-invoked dev-env tool, not a git hook.

- `reader.py` — `load_app()`; `@dataclass Endpoint(method, path, router, summary)`;
  `live_endpoints(app) -> list[Endpoint]`; `live_pairs(app) -> set[(method, path)]`;
  `committed_pairs(openapi_path) -> set[(method, path)]`.
- `render.py` — `render_catalog(endpoints) -> str`. Pure.
- `check.py` — `@dataclass Finding`; `check_openapi_fresh`, `check_catalog_in_sync`,
  `check_docs_reference_real`, `run_all(root=".") -> list[Finding]`. Non-blocking.
- `__main__.py` — `python -m tools.api {index|check}`.
- **Makefile** — `api-index` (writes `docs/api/index.md`) and `api-check`, each with
  a `##` doc (dogfooding D's convention).

## Edge cases

- **App import fails** (missing dep / env) → `run_all` returns a single Finding
  ("could not import src.main:app: …") and exits 0. The guard degrades to a warning,
  never a crash (mirrors the non-blocking contract).
- **Path-template param-name differences** — a route is `/exports/{interview_id}/{lens_name}`
  while a doc may write `/exports/{id}/{lens}`. `check_docs_reference_real`
  normalizes each path to its segment *shape* (literal segments kept, `{...}`
  segments collapsed to a placeholder) before comparing, so param naming doesn't
  cause false positives. The freshness and catalog checks compare live-vs-committed
  and live-vs-catalog respectively, both derived from the same app, so they use
  exact paths.
- **Auto-added routes** (`/openapi.json`, `/docs`, `/redoc`) are excluded — only
  `APIRoute`s whose endpoint module is under `src.api` are catalogued/compared.

## Testing

- **Unit** — `render_catalog` shape (grouped by router); `check_openapi_fresh` on a
  synthetic live-pairs set vs a synthetic committed set (added-only, removed-only,
  in-sync); `check_catalog_in_sync`; `check_docs_reference_real` (backticked real
  endpoint not flagged; backticked gone endpoint flagged; param-name difference not
  flagged; prose `/path` without backtick+method ignored); the import-failure path
  yields a Finding, not a raise. Use small hand-built `Endpoint`/pair fixtures — no
  real app import in unit tests.
- **Smoke** — `make api-index` writes `docs/api/index.md` with the real 34 endpoints;
  `make api-check` on the real repo exits 0 and is clean (openapi.json currently in
  sync at 34 paths).

## Non-goals (v1)

- **Endpoint→ADR governed-by overlay** — which ADR governs each router (natural
  v-next; reuses B's `code_links`; would surface a "governed by" column).
- **Field-level schema drift** — request/response body shapes, params, status codes.
  v1 compares the `(method, path)` surface only.
- **Live HTTP / running-server checks** — static app introspection only.
- **Wiring `api-check` into the git pre-commit hook** — it imports the app; kept as a
  `make` target.
- **Blocking** on any finding.
